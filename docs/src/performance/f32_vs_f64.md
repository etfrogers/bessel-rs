# Precision: f32 vs f64

Bessel functions involve intensive iterative algorithms, recurrence relations, and transcendental operations. As a result, calculating them in double precision (`f64`) requires significantly more computational power than single precision (`f32`).

Many real-world applications in computer graphics, audio processing, or machine learning only require 32 bits of precision. `amos-bessel-rs` provides generic algorithms bound by the `BesselFloat` trait, meaning you can drop in `f32` natively and gain significant performance benefits.

## Benchmark Results

*Note: All benchmarks were executed on an Apple M2 Pro (ARM64) using Rust 1.95.0. While absolute times will vary depending on your hardware, the comparative speedups should remain relatively consistent across modern CPU architectures.*

Below is a direct comparison of `f32` vs `f64` evaluation times using the Criterion framework. The benchmarks are split into two datasets:
- **Scattered**: An array of 46 highly extreme edge cases designed to trigger the slowest algorithmic paths (e.g., asymptotic expansions vs Miller algorithms).
- **Grid**: A realistic uniform grid of thousands of sequential points, designed to test typical throughput, caching, and branch prediction.

### Analysis

As shown above, `f32` is on average **over twice as fast** (2.13x) as `f64` across the entire suite of functions.

For the Airy functions (`Ai`, `Bi`), the speedup is particularly pronounced (approaching ~2.5x), reflecting their reliance on computationally heavy cube roots and fractional powers which execute much faster on `f32` ALUs. 

**Recommendation:** Unless your scientific workload strictly requires 64-bit IEEE 754 precision, you should default to `f32` arguments when evaluating large quantities of Bessel functions.
